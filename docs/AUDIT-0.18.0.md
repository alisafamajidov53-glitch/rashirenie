# Аудит и исправления 0.18.0

Продолжение [`AUDIT-0.17.0.md`](AUDIT-0.17.0.md). Документ описывает, что было
найдено полным аудитом кодовой базы и что из этого исправлено.

Состояние после правок: `npm run check` (lint → format → typecheck → test →
build) проходит полностью. Тестов стало 186 (было 101): 134 в
`@channelpilot/shared`, 49 в `@channelpilot/extension`, 3 в `@channelpilot/api`.

---

## 1. Безопасность

### 1.1 API-ключи больше не попадают в контент-скрипт

**Было.** `GET_SETTINGS` возвращал весь объект настроек, включая
`geminiApiKey`, `groqApiKey`, `twelveLabsApiKey` и `googleClientId`, любому
отправителю — в том числе контент-скрипту, который исполняется в процессе
рендерера youtube.com. Там же статически импортировался `lib/ai-direct`, то
есть ~58 КБ кода, выполняющего HTTP-запросы с этими ключами, линковались в
бандл контент-скрипта.

Отдельная ирония: `chrome.storage.local.setAccessLevel("TRUSTED_CONTEXTS")` в
`service-worker.ts` был выставлен правильно и полностью обнулялся этой выдачей
ключей по RPC.

**Стало.**

- Введён тип `PublicExtensionSettings` (`packages/shared/src/types.ts`) —
  проекция настроек без секретов, где вместо ключа отдаётся булев флаг
  готовности (`geminiReady`, `groqReady`, `twelveLabsReady`,
  `googleClientIdReady`).
- `toPublicSettings()` (`packages/shared/src/settings.ts`) — единственная точка,
  определяющая, какие поля считаются секретными.
- `GET_SETTINGS` в сервис-воркере различает отправителя по его origin
  (`isUntrustedSender()`) и отдаёт контент-скрипту только публичную проекцию.
  Первая версия проверяла `sender.tab` и ломала страницу настроек — см. §8.
- Состояние `uiSettings` в контент-скрипте типизировано как
  `PublicExtensionSettings`, поэтому попытка прочитать ключ теперь — ошибка
  компиляции, а не вопрос дисциплины.
- `TEST_AI_KEYS`, `LIST_AI_MODELS`, `SAVE_SETTINGS` и `RESET_LOCAL_DATA`
  отклоняются, если пришли из вкладки.

**Что осталось.** Анализ медиафайла — единственный путь, которому ключи всё ещё
нужны в контент-скрипте: объект `File`, выбранный пользователем в Studio, живёт
в этой вкладке и не переживает структурное клонирование при отправке в сервис-
воркер. Для него добавлен отдельный запрос `GET_MEDIA_ANALYSIS_SETTINGS`,
который:

- срабатывает только при явно включённом `allowAiMediaUploads`;
- принимается только от контент-скрипта с точного origin YouTube Studio;
- отдаёт только настройки AI-анализа и ключи провайдеров выбранного режима,
  без Google Client ID и остальных настроек;
- штатный контент-скрипт вызывает его при анализе медиа, а не при каждой
  загрузке страницы. Фоновый процесс проверяет origin и opt-in, но не может
  независимо подтвердить факт пользовательского жеста.

Полное устранение требует offscreen-документа, владеющего Blob, и передачи
файла по частям через порт. Это отдельная работа; текущая правка сокращает окно
экспозиции с «постоянно, на каждой странице YouTube» до «во время анализа,
инициированного пользователем, при включённой опции».

### 1.2 Контент-скрипт больше не может перезаписать чужие настройки

**Было.** Валидация `SAVE_SETTINGS` состояла из проверки «это объект» и
«сериализуется меньше 100 КБ». Ни одного поля не проверялось. Контент-скрипт мог
переписать `googleClientId`, то есть перенаправить OAuth на чужой клиент.

Кроме того, контент-скрипт сохранял позицию панели через read-modify-write всего
объекта настроек на каждый `pointerup`: перетаскивание панели молча откатывало
правку, сделанную в этот момент в кабинете.

**Стало.**

- `isSettingsShape()` в `packages/shared/src/messages.ts` проверяет тип каждого
  поля и отклоняет неизвестные ключи.
- Добавлено сообщение `SAVE_SETTINGS_PATCH` с белым списком
  `CONTENT_SETTABLE_SETTING_KEYS`: `generationLanguage`, `interfaceLanguage`,
  `showHeaderWidget`, `showLauncher`, `panelLayout`, `preferredProvider`.
  Всё остальное доступно только со страницы расширения.
- `sanitizeContentSettingsPatch()` прогоняет патч через полный нормализатор,
  поэтому вкладка не может прислать, например, панель шириной 99 999 px.
- Все четыре места в контент-скрипте переведены с read-modify-write на патч.

### 1.3 Права в манифесте

- `unlimitedStorage` — удалён. Рабочий набор ограничен 56 realtime-сериями
  (`realtime-store.ts`), которые при новом 5-минутном шаге занимают около 2 МБ
  при лимите по умолчанию 10 МБ. Chrome Web Store требует письменного
  обоснования этого права, а обоснования не было.
- `https://accounts.google.com/*` — удалён. `launchWebAuthFlow` не требует
  host-permission, а прямых запросов к этому origin в коде нет.
- `https://www.googleapis.com/*` — сужен до
  `https://www.googleapis.com/youtube/v3/*`. Было выдано разрешение на все
  Google API; реально используется только Data API.

### 1.4 Что проверено и оказалось в порядке

- **Mojibake в описании манифеста не подтвердился.** `dist/manifest.json` —
  валидный UTF-8 без BOM, описание декодируется корректно. Искажение в отчёте
  было артефактом чтения файла в PowerShell 5.1, который по умолчанию
  интерпретирует байты как CP1251.
- XSS через ответ модели: `innerHTML`, `dangerouslySetInnerHTML`, `eval`,
  `new Function`, `document.write` — ноль вхождений во всём `apps/extension/src`.
- Валидация OAuth `id_token` (`aud`/`iss`/`nonce`/`exp`), проверка `state`,
  проверка redirect-URI и выданных scope, revoke при выходе — сделаны
  корректно.
- Защита от prompt injection на уровне промпта и structured output — на месте.

## 2. Квота YouTube Data API

**Было.** Фоновый alarm с `periodInMinutes: 1`. Каждый сбор стоит 3 units
(`channels.list` + `playlistItems.list` + `videos.list`), то есть 4 320
units/сутки — 43% квоты проекта — при полном бездействии пользователя. Плюс
каждая открытая вкладка YouTube добавляла до 180 units/час.

При этом кэш запросов (`request-cache.ts`) жил в обычном `Map` внутри сервис-
воркера, который Chrome выгружает после ~30 секунд простоя. Повторный поиск
конкурента через две минуты снова стоил 103 units, хотя TTL кэша — 10 минут.

**Стало.**

| Изменение                                              | Экономия                   |
| ------------------------------------------------------ | -------------------------- |
| `REALTIME_ALARM_PERIOD_MINUTES` 1 → 5                  | 4 320 → 864 units/сутки    |
| `DASHBOARD_REALTIME_FRESH_MS` привязан к периоду alarm | вкладка не обходит alarm   |
| `MIN_REALTIME_COLLECTION_GAP_MS` 20 с → 2 мин          | нет дублей между вкладками |
| Кэш значений зеркалируется в `chrome.storage.session`  | TTL наконец работает       |

Совокупно фоновая нагрузка падает с ~58% квоты за рабочий день до ~9%.

**Обработка исчерпанной квоты.** Раньше при `403 quotaExceeded` alarm
продолжал срабатывать до полуночи по тихоокеанскому времени, получая только
ошибки, а пользователь видел техническое сообщение. Добавлены
`isQuotaExhaustedError()` и `millisecondsUntilQuotaReset()`: сбор ставится на
паузу до сброса квоты, а в интерфейсе появляется текст «квота исчерпана,
возобновится примерно через N ч».

**Не сделано.** `search.list` (100 units) остаётся дефолтным путём поиска
конкурента по названию (`youtube.ts:911-926`). Перевод его в явный opt-in — это
изменение пользовательского сценария, а не только кода; вынесено в бэклог.

## 3. Виджет и контент-скрипт

### 3.1 Клавиатура больше не уходит в плеер YouTube

Панель живёт в shadow root, поэтому для глобальных горячих клавиш YouTube
`event.target` ретаргетился на хост-элемент, а не на `<textarea>`. Проверка
«пользователь печатает в поле?» возвращала false, и страница обрабатывала
нажатие: пробел ставил видео на паузу, стрелки перематывали, `f` включал
полноэкранный режим, `m` выключал звук, цифры прыгали по таймлайну.

Добавлен `isolateKeyboard` на корне панели: `stopPropagation` на `keydown` и
`keyup` плюс обработка Escape для закрытия. Панель получила `role="dialog"`.

### 3.2 ErrorBoundary больше не перезагружает YouTube

Было `window.location.reload()` — в контент-скрипте это перезагрузка самой
страницы YouTube: потеря позиции в видео, а в Studio — потеря незаполненной
формы загрузки. Стало: пересборка поддерева через смену `key`. Компактный
вариант получил `position: fixed`, иначе фоллбэк рисовался блоком во всю ширину
в конце `<html>`.

### 3.3 Производительность

| Правка                                                                        | Что было                                                                                                       |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `resolvePanelLayout` возвращает ту же ссылку, если прямоугольник не изменился | ResizeObserver на `documentElement` ре-рендерил всё приложение при каждой подгрузке ленты                      |
| rAF-троттл на drag                                                            | `setPanelRect` вызывался на каждый `pointermove`, 60–120 раз в секунду                                         |
| MutationObserver наведён на `ytd-masthead`/`ytcp-header` + rAF-коалесинг      | наблюдение за `documentElement` c `subtree: true` аллоцировало MutationRecord на каждое изменение DOM страницы |
| Второй observer наведён на `ytcp-app`                                         | то же для `document.body` в Studio                                                                             |
| `adoptedStyleSheets` вместо `<style>`                                         | 85 КБ CSS парсились независимо в четырёх shadow-рутах                                                          |
| Динамический `import("../lib/ai-direct")`                                     | 58 КБ грузились на каждой странице YouTube                                                                     |

`ai-direct` по-прежнему числится в `web_accessible_resources` — иначе
динамический импорт из контент-скрипта не сработает, — но больше не
выполняется при загрузке страницы.

### 3.4 Корректность

- **SPA-навигация.** Был опрос `setInterval(detectNavigation, 750)`; виджет до
  750 мс показывал данные предыдущего видео. Добавлены слушатели
  `yt-navigate-finish`, `yt-page-data-updated`, `yt-navigate-redirect`; опрос
  оставлен страховкой с периодом 3 с.
- **Позиция дока.** Добавлен `ResizeObserver` на спейсер: изменение ширины
  шапки без мутации DOM (сворачивание гайд-меню, появление скроллбара, смена
  zoom) раньше оставляло виджет на старом месте до 10 секунд.
- **Обновление расширения.** Старый инстанс не размонтировался — оставались
  таймеры и слушатели, которые продолжали звать `rpc()` на инвалидированном
  контексте. Добавлено событие `channelpilot:shutdown` и честный
  `root.unmount()`.
- **`onLostPointerCapture`.** Без него потеря capture (например, из-за
  нативного drag) оставляла `panelInteractionRef` заполненным, и панель
  следовала за курсором с отпущенной кнопкой.
- **`useSuggestion` → `applySuggestion`.** Обычный обработчик клика назывался
  как хук; `react-hooks/rules-of-hooks` справедливо ругался.
- **Состояния загрузки.** При провале запроса `dashboard` оставался `null`, и
  ветка рендерила «Получаем профессиональную аналитику…» бесконечно — при том
  что пропсы `loading` и `onRefresh` в неё передавались и не использовались.
  Теперь три состояния: загрузка (со скелетонами), ошибка (с кнопкой
  «Повторить») и «на канале ещё нет видео».
- **Прилипающая ошибка.** Сбой сохранения позиции панели поднимал общий баннер
  ошибки, у которого нет кнопки закрытия, — одно неудачное перетаскивание
  оставляло сообщение поверх аналитики до конца сессии. Теперь это тихая
  операция: раскладка всё равно пересчитывается при следующей загрузке.

## 4. Дизайн

### 4.1 Акценты сведены в один источник

`useInterfacePreferences.ts` и `content/index.tsx` держали по собственной
таблице из четырёх акцентов, и **все восемь значений разошлись** — кабинет и
панель на YouTube показывали разный «фирменный» цвет.

Создан `packages/shared/src/theme.ts` с `ACCENT_PALETTES`. Обе поверхности
читают оттуда.

### 4.2 Контраст

Базовые тона акцентов пересчитаны так, чтобы белый текст на заливке проходил
WCAG AA (≥ 4.5:1):

| Акцент  | Было      | Контраст с белым | Стало     | Контраст |
| ------- | --------- | ---------------- | --------- | -------- |
| violet  | `#7b61ff` | 4.2:1            | `#5b43d6` | ≥ 4.5:1  |
| cyan    | `#20b8df` | 2.34:1           | `#0f6f8c` | ≥ 4.5:1  |
| emerald | `#24b985` | 2.51:1           | `#16785a` | ≥ 4.5:1  |
| coral   | `#f06478` | 3.09:1           | `#c62f47` | ≥ 4.5:1  |

Дополнительно у каждого акцента появился тон `onLight` — для текста и иконок на
светлом фоне.

### 4.3 Фокус-кольцо

Было `outline: 2px solid #a793ff` (кабинет) и `var(--purple-soft)` (popup) —
то есть кольцо тонировалось акцентом. В светлой теме это давало контраст
1.25:1 при cyan-акценте, то есть клавиатурный фокус был фактически невидим.

Стало: нейтральные токены `--focus-ring` и `--focus-halo`, которые
переключаются между тёмным и светлым в зависимости от темы и не зависят от
выбранного акцента. Добавлено во все три поверхности, включая панель в shadow
DOM, где раньше на 1400 строк стилей приходилось четыре правила с `outline`, а
кнопки закрытия меняли при фокусе только цвет текста.

### 4.4 Доступность

- Добавлены блоки `@media (prefers-contrast: more)` и
  `@media (forced-colors: active)` — раньше ноль вхождений во всех трёх CSS,
  и Windows High Contrast ломал стеклянные поверхности целиком.
- Тап-таргеты `.cp-close`, `.cp-minimize` (31 px) и `.cp-launcher-hide`
  (24 px) расширены до ~45 px через `::before { inset: -7px }` — иконка
  осталась прежнего размера.
- Мелкий текст в состояниях загрузки поднят с 11 px до 12–13 px.
- Скелетоны отключаются при `prefers-reduced-motion` и в режиме
  `data-motion="reduced"`.

## 5. Инфраструктура

### 5.1 ESLint

Было шесть базовых правил. Добавлены:

- `@typescript-eslint/no-floating-promises` и `no-misused-promises` — с
  `projectService: true`, без которого type-aware правила молча не работают.
  Потерянный промис в сервис-воркере не всплывает нигде: воркер может быть
  выгружен раньше, чем rejection будет замечен.
- `await-thenable`, `no-explicit-any`, `ban-ts-comment`,
  `no-unnecessary-type-assertion`.
- `react-hooks/rules-of-hooks` (error) и `exhaustive-deps` (warn).

Найдено и исправлено сразу: один потерянный промис, три лишних type assertion,
функция-обработчик с именем хука.

Оставшиеся 7 предупреждений `exhaustive-deps` — существовавшие ранее; их
починка меняет поведение и вынесена отдельно.

### 5.2 Тесты под tsc

`apps/extension/tsconfig.json` не включал каталог `test`, поэтому
`npm run typecheck` его не проверял. Аналогично в `shared` и `api`, где
конфиг одновременно отвечал за сборку (`rootDir: "src"`) — добавить туда тесты
было нельзя.

Разделено: `tsconfig.json` (проверка, `src` + `test`, `noEmit`) и
`tsconfig.build.json` (эмит, только `src`). Сразу после включения tsc нашёл две
реальные ошибки в `twelvelabs-direct.smoke.ts`.

### 5.3 Новые тесты

`packages/shared/test/settings-boundary.test.ts` — 14 кейсов на границу
безопасности: что `toPublicSettings` действительно вырезает все секреты
(проверка по сериализованной строке, а не только по ключам объекта), что
`sanitizeContentSettingsPatch` отбрасывает `googleClientId` и ключи провайдеров,
что `isExtensionRequest` отклоняет патч за пределами белого списка, что
`resolvePanelLayout` возвращает ту же ссылку при неизменившемся прямоугольнике
и по-прежнему клампит в вьюпорт, и что `allowAiMediaUploads` по умолчанию
выключен.

### 5.4 CI

Добавлен `.github/workflows/ci.yml`, запускающий `npm run check` — ту же
команду, что и локально, чтобы пайплайн не мог разойтись с тем, что видит
разработчик.

**Git не инициализирован** — на машине не установлен `git`, поэтому
репозиторий создать не удалось. 27 800 строк по-прежнему живут без истории и
без возможности отката. Это первое, что стоит сделать вручную.

## 7. Что осталось в бэклоге

Упорядочено по отношению пользы к риску.

1. **`git init` и первый коммит.** Требует установки git.
2. **Offscreen-документ для медиа-анализа** — закрывает последний путь, по
   которому ключи попадают в контент-скрипт.
3. **`search.list` в явный opt-in** — снимает до 3 000 units/сутки в типовом
   сценарии работы с конкурентами.
4. **Миграция OAuth на Authorization Code + PKCE.** Сейчас используется
   implicit flow, который у Google deprecated: нет refresh-токена, а
   `prompt=none` зависит от сторонних куки.
5. **Тесты на background-слой** — 0 тестов на 2 178 строк
   (`service-worker.ts`, `google-auth.ts`, `youtube.ts`).
6. **Распил файлов-монстров**: `options/main.tsx` (7 346 строк),
   `content/index.tsx` (4 551).
7. **Подключение `apps/api/` как серверного хранилища ключей.** Это снимает
   главный барьер онбординга: сейчас пользователь обязан сам завести проект в
   Google Cloud, включить два API и создать OAuth-клиент. См. решение ниже.
8. **Удаление старого слоя CSS** — `options.css:1-5013` (71% файла) и
   `styles.ts:1-916`. В проекте 1 011 уникальных hex-значений, 839 из них
   встречаются ровно один раз.
9. **Privacy Policy** — обязательна для публикации: расширение читает данные
   YouTube-аккаунта и передаёт контент видео третьим сторонам.
10. **Ключ `key` в манифесте** должен совпадать с загружаемым в Chrome Web
    Store элементом либо быть удалён перед публикацией.

## 8. Критическая регрессия в 1.1 и её исправление

Разграничение «страница расширения против контент-скрипта» было сделано по
`sender.tab`. Это неверно: **страница настроек открывается во вкладке**, поэтому
у неё `sender.tab` определён так же, как у контент-скрипта. Кабинет стал
считаться недоверенным источником и получал настройки без API-ключей, а
`SAVE_SETTINGS`, `TEST_AI_KEYS`, `LIST_AI_MODELS` и `RESET_LOCAL_DATA`
отклонялись с ошибкой. Страница падала в ErrorBoundary.

Правильный признак — origin отправителя: контент-скрипт сообщает origin
страницы (`https://www.youtube.com`), а любая страница расширения —
`chrome-extension://<id>`. Реализовано в `isUntrustedSender()`
(`background/service-worker.ts`), с фоллбэком на `sender.url` для Chrome
старше 80 и отказом по умолчанию, если нет ни того ни другого.

Покрыто шестью тестами в `apps/extension/test/sender-trust.test.ts`, включая
случай «origin, который лишь начинается с origin расширения».

Там же исправлена вторая регрессия: ErrorBoundary оборачивал children в
`<div style="display:contents">`. Это лишний узел в DOM, который ломает
селекторы вида `.parent > .child` в таблицах стилей. Заменено на
`<Fragment key={generation}>` — ремонтирование без узла.

Поздний «glass»-слой хардкодит тёмные значения (`rgba(9, 10, 17, …)`) и

липкую полосу действий и акцентную карточку.

кромке — визуально неотличимо от «метрика равна нулю». Тот же порог в 1
сплющивал любой ряд с размахом меньше единицы (доли удержания, просмотры в
минуту).

Геометрия вынесена в `packages/shared/src/sparkline.ts`: ряд без вариации
рисуется по середине, используется реальный размах. Покрыто восемью тестами.

Дважды за эту сессию backtick внутри CSS-комментария молча обрывал
template-литерал `panelStyles`. Добавлен `apps/extension/test/styles.test.ts`:

## 10. Второй проход по дизайну: найденные ошибки вёрстки

### 10.1 Панель открывалась поверх шапки YouTube

Место по умолчанию — 12px от верха, то есть прямо на 56-пиксельной sticky-шапке
YouTube. Панель накрывала поиск, меню аккаунта и **собственный виджет
расширения** — пользователь открывал панель и терял из виду то, ради чего её
открыл.

`resolvePanelLayout` получил `DEFAULT_TOP_OFFSET = 68`: панель без сохранённой
позиции открывается под шапкой и её высота по умолчанию считается от этого
смещения (иначе кламп по нижней границе всё равно затягивал её обратно наверх).
Сохранённая позиция по-прежнему соблюдается буквально — поставить панель на
шапку можно, это выбор пользователя. Четыре теста в `panel.test.ts`.

### 10.2 Дыра в шапке YouTube на узких окнах

`@media (min-width: 521px) and (max-width: 900px) { .cp-realtime.panel-open
{ display: none } }` скрывало виджет при открытой панели — включая **встроенный
в шапку** вариант. Его 212-пиксельная распорка при этом оставалась в разметке
шапки: в интерфейсе YouTube рядом с поиском зияла пустая полоса.

Правило сужено до `.cp-realtime.undocked.panel-open`: отступает только плавающий
виджет, которому действительно есть с чем конфликтовать.

### 10.3 Все подписи в доке схлопывались в многоточие

Арифметика: при ширине дока 212px и `padding: 0 10px` на кнопке под подпись
оставалось 25px. Результат — «60 …», «24 Ч…», «ВСЁ ВРЕ…».

- Паддинг кнопки 10px → 6px.
- Размер подписи 9.5px → 10px, трекинг 0.34 → 0.18.
- «Всё время» → «Всего» (`All time` → `Total`): длинная формулировка не
  помещалась ни на одной ширине ниже 1700px.
- Ниже 1180px, где доку достаётся ≤234px, третья метрика скрывается: две
  читаемые лучше трёх обрезанных.

Отдельно всплыла причина, по которой первая попытка не сработала: правило в
`@media (max-width: 1700px)` стоит ниже по файлу и при равной специфичности
побеждало. Брейкпоинты дока пересобраны по порядку от широкого к узкому.

### 10.4 Липкая полоса действий разрезала текст

Скрим над закреплённой полосой был 16px и обрывался посреди строки. Увеличен до
32px с трёхточечным градиентом — строка уходит под полосу целиком, а не
разрезается пополам. Светлая тема получила ту же кривую.

### 10.5 Оптимизация рендера

- `RealtimeWidget` и `AnalyticsView` обёрнуты в `memo`. До этого все четыре
  колбэка виджета пересоздавались на каждый рендер `App`, поэтому `memo` всё
  равно бы не сработал — идентичности стабилизированы через ref, который
  обновляется каждый рендер (без списка зависимостей и без устаревших
  замыканий).
- Разделён `useEffect`, который совмещал начальную загрузку настроек с
  перехватом файлов в Studio. Из-за общего списка зависимостей смена языка или
  тумблера медиа повторно дёргала `GET_SETTINGS` и `AUTH_STATUS` **и вызывала
  `setPanelRect` с сохранённой раскладкой**, отбрасывая позицию, которую
  пользователь только что перетащил.

### 10.6 Мёртвый код

Удалены 7 неиспользуемых классов: `cp-copy-row`, `cp-latest-video`,
`cp-live-grid`, `cp-video` (виджет), `chart-footer`, `dashboard-sparkline`,
`editor-page` (кабинет) вместе с их правилами в светлых темах.

Проверка на неиспользуемые экспорты в `packages/shared` дала 14 кандидатов —
все оказались типами возвращаемых значений используемых функций. Удалять их
было бы неверно, поэтому не тронуты.

Кандидаты `align-icon-center`, `align-icon-right`, `format-16-9`, `format-9-16`
оказались ложными срабатываниями: имена собираются динамически
(`` `align-icon-${value}` ``, `` `format-${format.replace(":", "-")}` ``).

### 10.7 Устаревший тест

`dashboard.test.tsx` проверял наличие строк «Behind the numbers» и «Growth in
context», которых в исходниках больше нет вообще. Заменено на структурные
проверки (`.dashboard-shell`, `.metric-card`, `.analytics-video-row` и имя
канала из фикстуры) — привязка к маркетинговому тексту и была причиной поломки.

## 12. Мёртвая кнопка «Открыть кабинет» и разбор вёрстки кабинета

Поводом стали два скриншота: в виджете не работала кнопка «Открыть кабинет», а
на странице «Видео и рост» текст одной колонки печатался поверх соседней.

### 12.1 Кнопка «Открыть кабинет» ничего не делала

**Причина.** Контент-скрипт получает не весь `chrome.*`, а срез: из
`chrome.runtime` доступны только `connect`, `getManifest`, `getURL`, `id`,
`onConnect`, `onMessage` и `sendMessage`. `openOptionsPage` в этот список не
входит — в изолированном мире его просто нет. Пять обработчиков в
`content/index.tsx` вызывали `chrome.runtime.openOptionsPage()`; вызов бросал
`is not a function`, React гасил исключение, кнопка нажималась и не делала
ничего.

`tsc` этого не ловит: `@types/chrome` объявляет весь API независимо от
контекста, в котором файл будет выполняться.

**Исправление.** Добавлено сообщение `OPEN_OPTIONS_PAGE`; сервис-воркер, у
которого полный API, открывает страницу сам. В контент-скрипте появилась
функция `openDashboard()` — единственная точка, через которую идут все пять
кнопок. Fallback через `window.open` сознательно не делался: страница настроек
не объявлена в `web_accessible_resources`, и переход на неё со страницы сайта
Chrome блокирует, так что это была бы видимость запасного пути.

**Защита от повторения.** `apps/extension/test/content-chrome-api.test.ts`
разбирает исходник контент-скрипта (без комментариев) и падает на любом
обращении к `chrome.*` вне доступного контент-скрипту среза. Этот тест сразу
нашёл пятый, ранее пропущенный вызов в `InlineAssistant`.

### 12.2 Таблица «Видео и рост»

Системная причина одна: набор колонок был подобран под подписи 10px, а более
поздний «пол читаемости» (`.dashboard-shell small, …`) поднял их до 12px. После
этого колонки перестали вмещать собственное содержимое.

| Симптом                                                               | Причина                                                                                           |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `Performance 73/100 · high` печатался поверх кнопок строки            | `white-space: nowrap` без `overflow: hidden` — текст рисуется за пределами своей ячейки           |
| «AI-анализ» переносился на две строки, кнопка становилась 46px        | колонка 164px при потребности 168px, переносы не запрещены                                        |
| «ПОДПИСКИ · 28Д» уезжало на вторую строку и ломало выравнивание шапки | `.dashboard-shell button { font-size: 13px }` побеждал `.table-sort { font: inherit }` по весу    |
| Заголовок ролика обрезался после 4–5 слов                             | на колонку оставалось 115px текста при жёстких `90px 100px 76px …`                                |
| Кнопки строки были не видны на 1280–1450px                            | восьмиколоночная сетка требует ~1095px, а сворачивалась только ниже 1240px — остальное обрезалось |

Что сделано:

- Треки переведены на `minmax(min, fr)`; каждый минимум равен самой широкой
  строке, которую колонка реально печатает по-русски, а доли `fr` отдают
  лишнюю ширину широкого монитора заголовку. Обе сетки остаются независимыми от
  контента: шапка и каждая строка — отдельные grid-контейнеры, и трек `auto`
  разошёлся бы у них по-разному.
- Заголовок ролика — две строки вместо одной с многоточием.
- `.momentum-score` обрезается по своей ячейке, а `Performance 73/100 · high`
  заменён на локализованный `73/100 · высокая` с полным пояснением в `title`.
- Колонка «Статус» получила класс `.status-cell` вместо анонимного `div`.
- Плотные подписи таблицы выведены из общего «пола читаемости» на 11px —
  отдельным правилом с объяснением, почему именно здесь 12px не подходит.
- Действия строки сворачиваются на 1459px, а не на 1240px. Диалог подробностей,
  который открывается по заголовку, несёт «Перейти к AI-анализу» и ссылку на
  Studio; редактор превью остаётся на своей странице в боковом меню. Это
  сознательный размен: на 1440px мы оставляем превью ролика и все семь метрик,
  а три кнопки уводим на один клик вглубь.
- `min-width` для планшетного горизонтального скролла исправлен с 780px на
  918px — прежнее значение было меньше минимума самой сетки, поэтому треки
  вылезали из строки вместо того, чтобы прокручивать карточку.

### 12.3 Обзор

- **`.ai-ideas` была единственной секционной карточкой без `padding`** — её
  заголовок и кнопка «Сгенерировать идеи» лежали вплотную к границе карточки.
- **Разбивка «Новые / вернувшиеся»** — пятая карточка в четырёхколоночной
  сетке — оставалась одна на втором ряду в четверть ширины. Это сноска об
  отсутствующей метрике, а не пятая метрика: теперь она на всю ширину, с
  пояснением рядом с заголовком.
- Подписи разбивок (9px) подняты до 11px и переносятся на вторую строку вместо
  многоточия: «Неподписанные зрители» превращалось в «Неподписанные…».

### 12.4 Адаптивность

Проверено на 320 / 375 / 390 / 430 / 768 / 1024 / 1280 / 1440 / 1512 / 1920.
Найдено и исправлено:

- **1241–1345px**: `.editor-layout` с `minmax(560px, 1fr) 420px` давал 1000px
  при меньшем доступном месте и уводил всю страницу в горизонтальный скролл.
- **721–1040px**: тулбар комментариев из пяти колонок требовал ~885px и
  сворачивался только ниже 720px.
- **768px**: `.page-intro` не переносился, а `h1` с `clamp(30px, 3vw, 43px)` не
  сжимается ниже самого длинного слова — переключатель периода выдавливало за
  экран.
- **≤720px**: шесть перенесённых кнопок делали липкую шапку 160px высотой, то
  есть пятой частью экрана телефона поверх липкой нижней навигации. Шапка
  теперь уезжает вместе со страницей.
- **≤720px**: в карточной раскладке строки `flex: 1` стоял на ссылке «↗», и
  безымянная стрелка занимала треть ряда, сжимая подписанные действия.

Горизонтального скролла страницы больше нет ни на одной ширине; остаётся
намеренный скролл внутри карточки таблицы и внутри доски планера.

### 12.5 Светлая тема

- Кнопки действий строки (`#19181f` на белой карточке) и чипы статуса
  (`#3f281a`, `#173629`, `#2b263f`, `#27262e`) не имели светлых вариантов —
  почти чёрные плашки на белом фоне в каждой строке таблицы.
- То же в popup: `.live-pill` оставался тёмно-зелёным на светлой карточке
  канала.

Проверка контраста по всем страницам (текст поверх плоских фонов, с пропуском

### 12.6 Единая система

## 13. Настраиваемый виджет и liquid glass

### 13.1 Состав виджета редактируется

Раньше виджет был фиксированным: три метрики в строке YouTube и пять блоков в
развёрнутой карточке. Теперь оба списка — обычные настройки
(`widgetSections`, `widgetDockMetrics`) с моделью в
`packages/shared/src/widget.ts`.

**На самой странице** — кнопка ⚙ в шапке развёрнутой карточки включает режим
настройки. Реальные блоки остаются на экране, у каждого появляются ↑ ↓ ×, а
внизу — панель «Добавить блок» и переключатели метрик строки, «Вернуть по
умолчанию» и «Готово». Изменения применяются сразу (оптимистично) и
сохраняются через `SAVE_SETTINGS_PATCH`; оба поля добавлены в белый список
контент-скрипта.

**В кабинете** — тот же редактор в «Подключения → Интерфейс в YouTube». Он
нужен не для дублирования: если скрыть виджет или убрать все блоки, редактор на
странице становится недоступен, а вернуть их должно быть можно.

Пустые состояния продуманы: без блоков карточка показывает «Все блоки убраны» с
кнопкой «Вернуть блоки»; без метрик строка показывает «ChannelPilot ·
Аналитика» вместо пустой капсулы.

Переупорядочивание сделано кнопками, а не перетаскиванием: виджет живёт в
shadow root на странице с собственными обработчиками указателя, а кнопки
работают с клавиатуры без дополнительной логики.

### 13.2 Клавиатура в редакторе

Каждое действие перерисовывает или убирает кнопку, которая его вызвала, и
фокус уходил в `<body>` после каждого шага. Теперь:

- после ↑/↓ фокус остаётся на той же стрелке перемещённого блока, а если блок
  дошёл до края и стрелка стала неактивной — на соседней;
- после × фокус переходит на чип «+ блок», который его возвращает, — случайное
  удаление отменяется одним Enter;
- после добавления фокус на стрелке ↑ нового блока;
- Escape снимает слои по одному: сначала выход из редактора, потом сворачивание;
- «Готово» и Escape возвращают фокус на кнопку ⚙ — через эффект, а не
  `requestAnimationFrame`, который не срабатывает в фоновой вкладке.

### 13.3 Строка метрик

- Сетка `repeat(3, …)` заменена на flex — метрик может быть от нуля до пяти.
- Ширину резервируемого места в шапке YouTube теперь считает
  `dockWidthForMetrics()` по числу метрик; при трёх она совпадает с прежними
  значениями (288 / 273 / 255 / 212 px), это закреплено тестом.
- Ниже 1180px видны первые две метрики, остальные — в развёрнутой карточке;
  там же `dockWidthForMetrics` перестаёт добавлять ширину.
- Подписи сокращены до «60 мин / 24 ч / 48 ч / Всего / Подп.»: при пяти
  метриках «48 ЧАСОВ» и «ПОДПИСКИ» уходили в многоточие. Полные названия — в
  подсказке и в редакторе.
- Метрики в строке всегда идут в порядке окна (60 мин → всё время), а не в
  порядке, в котором их включили.

### 13.4 Liquid glass

- Все внутренние поверхности виджета собраны из одного рецепта (четыре
  переменные `--cp-glass-*`). Строки «Набирают сейчас», «Приводят подписчиков»
  и карточка входа были непрозрачными плашками `#1c1b20` / `#191720` рядом с
  полупрозрачными KPI — одинаковые карточки выглядели по-разному.
- Светлая тема перекрывала этот рецепт сплошным `#ffffff` с большей
  специфичностью, так что стекла в ней не было вовсе. Переопределение фона
  убрано, остался только цвет текста.
- Бликовая кромка сверху у капсулы и у развёрнутой карточки.
- Выбранная метрика в строке — стеклянная «пилюля» внутри капсулы. Раньше это
  был прямоугольник на всю высоту с прямыми углами внутри скруглённой формы, а
  поверх него ещё рисовалось подчёркивание из предыдущего дизайна.
- Плитки «Эффективность» в панели — последняя плоская заливка (`#1b1722`) —
  переведены на общее стекло.
- `backdrop-filter` только у внешних поверхностей и редактора: размытие на
  каждой строке стоило бы слой композиции на строку.

### 14.2 Обзор

- График сравнивает период с предыдущим окном той же длины: пунктирная «тень» на одной шкале, процент изменения рядом с суммой, в подсказке — значение того же дня раньше. Тень рисуется только если предыдущее окно полное, иначе сравнение неравных отрезков выглядело бы падением. Отключается флажком.
- Подпись «28 ДНЕЙ» над графиком была неправдой при выборе 7 или 14 дней — заменена.

### 14.3 Видео и рост

- Поиск ищет по названию, тегам и ID, без учёта регистра и «ё/е», и по каждому слову отдельно («mobs 2026» находит «Minecraft Mobs Evolution: 2009 to 2026»).
- «/» ставит фокус в поиск, Escape очищает его.
- Запрос, сортировка и формат переживают уход со страницы (на время вкладки); у превью таблицы на обзоре своё состояние.

### 14.4 Планер

- Пятая колонка «Опубликовано» на 1512px была наполовину за горизонтальной прокруткой — колонки ужаты с 230 до 196px минимум и теперь помещаются.
- Пустые колонки подсказывают «Перетащите карточку сюда» (или «Ничего не найдено» при поиске); колонка под перетаскиваемой карточкой подсвечивается.
- Удаление карточки вместе с заметками было мгновенным и окончательным. Теперь 8 секунд можно нажать «Вернуть» — карточка возвращается на своё место.
- Фикстура стенда не сохраняла рабочее пространство, и планер в стенде не работал вовсе — исправлено.

Тесты: `planner.test.tsx` (2) — удаление с возвратом и исчезновение предложения через 8 секунд.
